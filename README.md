Evaluación de Herramientas de Vibe Coding

Objetivo

Este proyecto tiene como objetivo evaluar distintas herramientas de programación asistida por IA y elegir cuáles se adaptan mejor a mis necesidades actuales como desarrolladora.

La evaluación no se basa únicamente en qué herramienta genera código más rápido, sino también en cuánto control permite mantener sobre el proyecto, cuánto ayuda a aprender y comprender el código, y qué tan bien se integra con un flujo de trabajo real usando archivos locales, Git y GitHub.

Mis criterios personales

Para elegir una herramienta de Vibe Coding, priorizo:

Aprendizaje antes que velocidad: prefiero tardar un poco más si eso me ayuda a entender lo que estoy haciendo.

Explicación antes de modificar: quiero que la IA explique qué propone cambiar y por qué antes de aplicar cambios.

Control sobre el código: prefiero revisar y comprender las modificaciones antes de aceptarlas.

Trabajo con proyectos reales: valoro poder trabajar localmente y usar Git y GitHub.

Flexibilidad: no me molesta que una herramienta sea algo más compleja si ofrece más control.

Costo: estoy dispuesta a pagar una suscripción si realmente mejora mi aprendizaje y productividad.

Mantenibilidad: prefiero herramientas que me ayuden a producir código que pueda seguir entendiendo y modificando más adelante.

Prueba práctica con Cursor

Para no basar la evaluación únicamente en características teóricas, probé Cursor con un proyecto React real.

El proyecto utilizado fue una Todo List desarrollada previamente.

Flujo de prueba

Abrí el repositorio localmente en Cursor.

Le pedí que analizara la estructura del proyecto sin modificar nada.

Cursor explicó los archivos principales y la lógica del componente.

Le pedí tres mejoras pequeñas que me permitieran practicar React.

Elegí agregar tareas usando la tecla Enter.

Antes de modificar el archivo, le pedí que explicara exactamente qué cambiaría y por qué.

Cursor explicó el uso de:

<form>

onSubmit

preventDefault()

Después le permití aplicar el cambio.

Revisé el diff antes de continuar.

Ejecuté el proyecto localmente y comprobé que:

el botón + seguía funcionando;

la tecla Enter también agregaba tareas;

la página no se recargaba.

Resultado de la prueba

La experiencia fue positiva porque Cursor respetó las instrucciones, explicó los cambios antes de realizarlos y permitió revisar el resultado.

Esto reforzó mi valoración de 5/5 para mis necesidades actuales.

Herramientas que elegiría actualmente

No considero que exista una única herramienta perfecta para todo.

Mi combinación ideal actualmente sería:

ChatGPT

Para:

aprender;

resolver dudas;

analizar errores;

entender conceptos;

pensar soluciones antes de implementarlas;

revisar estrategias y requisitos.

Cursor

Para:

trabajar directamente dentro del proyecto;

leer y modificar archivos;

revisar cambios mediante diff;

aplicar mejoras de forma controlada;

trabajar con Git y proyectos locales.

GitHub

Para:

repositorios;

ramas;

commits;

Pull Requests;

Más adelante también me interesa probar GitHub Copilot y Claude Code para comparar sus flujos de trabajo con Cursor.

Conclusión

La herramienta que mejor se adapta a mis necesidades actuales es Cursor, especialmente porque me permite combinar IA con un flujo de desarrollo real sin perder el control sobre el código.

Sin embargo, mi prioridad no es utilizar la herramienta que haga más cosas automáticamente, sino la que me permita aprender, comprender y tomar decisiones sobre el código que estoy desarrollando.

Para mí, la mejor forma de usar IA en programación es:

pensar → preguntar → entender → revisar → aplicar → probar

La IA puede acelerar el trabajo, pero la comprensión y la decisión final deben seguir siendo responsabilidad del desarrollador.
